# Skills and Engineering Strengths

My strongest practical skill right now is building modern web applications with JavaScript/TypeScript, particularly React and Next.js. Next.js is a comfort zone because I have used it across several different kinds of work rather than only following tutorials: public-facing sites, admin interfaces, API-backed forms, Sanity-powered content, SEO work, server actions/route handlers, caching, and ISR. TypeScript is useful to me not just as a syntax layer but as a way of making boundaries explicit between UI state, API data, validation, and application logic. I am also comfortable with Git, REST-style APIs, form validation, asynchronous data fetching, and the general workflow of taking a web feature from requirement to working application.

I am deliberately moving beyond frontend-only work. My backend exposure includes Node.js concepts and API work, while my current deeper backend direction is .NET: C#, ASP.NET Core, gRPC, PostgreSQL, Entity Framework Core, service contracts, and basic distributed-system architecture. I have been building small services and a marketplace-style system to learn how services communicate, how data should be modeled, and where responsibilities should live. I would not describe myself as an experienced backend engineer yet; that is precisely the area I am building toward. The combination I want is frontend competence plus enough backend and systems understanding to own a feature across the stack instead of handing everything behind the API boundary to someone else.

Other areas I have worked with include Vue, Vuex, Vue Router, Axios, Sanity, TurboRepo, SWR, Zod, testing with Jest/Vitest, Tailwind, PostgreSQL, Docker/cloud fundamentals, and basic Linux/AWS concepts. I learn best by implementing systems and then dealing with the engineering problems they expose, rather than collecting technologies as a list.
