# Pristine Reader

Pristine Reader is a browser-side reading project focused on turning messy web pages into cleaner reading experiences. The idea was conceived by my friend and batchmate in college, Azlan Ibrahim, a very talented design engineer. He told me about the idea and was struggling to figure out a way to clean the messy web-pages on the internet to make them more readable. This was the technically interesting part to me, the DOM-cleaning algorithm: rather than simply hiding a fixed list of selectors such as `aside`, `.ads`, or `.sidebar`, the application tries to decide which parts of an arbitrary page are likely to be useful content and which parts are clutter.

I had been a FireFox user ever since I got a laptop. Rather recently, Mozilla launched a reader mode feature built-in to FireFox. Back then it did not work very well. It could only remove the wrappers on the elements with text and media, and then put the remaining elements together. It didn't care about the sizing, fonts, nested lists, tabular structures, links with spans, and there were numerous edge cases that it wouldn't work on. I found the library Mozilla was using for the DOM cleaning. It was a public repository on GitHub. We took that, and built on top of it. We spent days finding dirty websites with articles, blogs with ads and bad structures and would stare at the browser's elements tab thinking of what structure is most meaningful here and how can we get it. We ended up creating a browser extension that worked better than FireFox's reading mode back then, had storage and management features, a voice reader, syntax highlighting and note taking.

The algorithms we wrote reasoned about the structure of the DOM and the characteristics of elements and their surroundings. Content-heavy regions tend to contain meaningful text and paragraphs, while navigation, promotional blocks, repeated links, controls, metadata, and other peripheral structures have different structural and textual signals. The cleaner therefore has to make a judgment about an element's role rather than relying on one universal CSS class. This is difficult because real websites are inconsistent and messy: an element that looks like navigation on one site can be part of the article on another.

That trade-off is what makes the project interesting. Aggressive cleaning can produce a beautifully minimal page while accidentally deleting something important; conservative cleaning leaves more clutter behind. Pristine Reader is an exercise in building a heuristic DOM transformation system where the definition of “clutter” has to emerge from several imperfect signals rather than a single rule.
